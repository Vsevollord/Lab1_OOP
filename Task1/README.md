# Лабораторная 1 — Задание 1: Объектная модель уравнений

Консольное приложение на C++, реализующее объектную модель математических
уравнений с полиморфизмом, инкапсуляцией и иммутабельным типом комплексного
числа.

## Содержание

- Назначение
- Архитектура
- Классы
- Тесты

---

## Назначение

Программа демонстрирует:

- **инкапсуляцию** — внутреннее состояние классов скрыто (`private`);
- **наследование** — `LinearEquation` и `SquareEquation` являются `Equation`;
- **полиморфизм по подтипу** — работа с уравнениями через общий тип `Equation*`;
- **специализированный полиморфизм** — перегрузка операторов и функций;
- **иммутабельность** — `Complex` не изменяется после создания;
- **функтор** — уравнение вызывается как функция через `operator()`;
- **коллекцию через общий тип** — `EquationSet` хранит и обрабатывает разные
  уравнения единым алгоритмом.

## Архитектура

```
┌─────────────────────────────┐
│  Equation (abstract)        │
│  + calculate() : vector<C>  │  virtual = 0
│  + operator()(x) : Complex  │  virtual = 0   (функтор)
│  + print(os)                │  virtual = 0
│  + ~Equation()              │  virtual
└─────────────┬───────────────┘
              │ is-a
   ┌──────────┴───────────┐
┌──▼───────────────┐  ┌───▼──────────────┐
│ LinearEquation   │  │ SquareEquation   │
│ ax + b = 0       │  │ ax² + bx + c = 0 │
│ a, b  (a != 0)   │  │ a, b, c (a != 0) │
└──────────────────┘  └──────────────────┘

EquationSet — коллекция через общий тип

Complex — иммутабельный value-тип:  + - * / == != <<
```

## Классы

### `Complex` — комплексное число (иммутабельное)

| Элемент | Описание |
|---|---|
| `Complex()` | `0 + 0i` |
| `Complex(double)` | `a + 0i` |
| `Complex(double, double)` | `a + bi` |
| `get_re()`, `get_im()` | доступ к компонентам |
| `+ - * /` | арифметика; возвращают **новый** объект |
| `== !=` | сравнение |
| `operator<<` | вывод (`2+3i`, `-1-2i`, `5`) |

Деление на ноль (`Complex(0,0)`) бросает `std::invalid_argument`.

### `Equation` — абстрактный базовый класс

Чисто виртуальные методы:
- `std::vector<Complex> calculate()` — решение;
- `Complex operator()(const Complex& x) const` — значение функции (**функтор**);
- `void print(std::ostream&) const` — вывод;
- виртуальный деструктор.

### `LinearEquation : Equation`

Уравнение `ax + b = 0`, `a != 0` (иначе `std::invalid_argument`).
Один корень: `x = -b / a`.

### `SquareEquation : Equation`

Уравнение `ax² + bx + c = 0`, `a != 0` (иначе `std::invalid_argument`).
- `D > 0` — два вещественных корня;
- `D = 0` — один корень;
- `D < 0` — два комплексно-сопряжённых корня.

### `EquationSet` — коллекция уравнений

Хранит `std::vector<Equation*>` (**non-owning**: не владеет уравнениями).

| Метод | Описание |
|---|---|
| `add(Equation*)` | добавить; `nullptr` → `std::invalid_argument` |
| `calculateAll()` | решить все |
| `calculateInPoint(x)` | значения всех в точке `x` |
| `haveRoot(x)` | уравнения, для которых `f(x) = 0` (с `eps = 1e-9`) |
| `size()` | количество |
| `printEquation(i)` | вывод `i`-го уравнения |


## Тесты

Тесты запускаются автоматически в `main()` **до** демонстрации.
В конце печатается:

```
Failed: N | Passed: M of N+M tests
```
Покрыты:

- `Complex`: `+ - * / == !=`, дефолт, конструктор от `double`,
  **неизменность операндов**, деление на ноль;
- `LinearEquation`: корень, `f(x)`, `f(i)`, `f(root) = 0`, `a = 0` → исключение;
- `SquareEquation`: `D > 0`, `D = 0`, `D < 0`, `f(complex root) = 0`, `a = 0` → исключение;
- `EquationSet`: пустая коллекция, добавление, решение всех, значения в точке,
  поиск по корню (вещественному, комплексному, `√2`, отсутствующему),
  `add(nullptr)` → исключение.

## Принятые решения

| Решение | Почему |
|---|---|
| Абстрактный `Equation` + virtual | полиморфизм по подтипу, OCP: новое уравнение — новый наследник |
| `vector<Equation*>` non-owning | объекты живут на стеке в демо/тестах; владение — у вызывающего кода |
| Свой `Complex` вместо `std::complex` | требование задания + перегрузка операторов |
| `vector<Complex>` как результат | единый тип для любого числа корней |
| Исключения (`std::invalid_argument`) | нарушение инварианта — исключительная ситуация |
